# Apartment Management — стартовый шаблон

Учебный фронтенд проекта «Кабинет арендодателя». Реализованы инфраструктура, авторизация, маршрутизация и базовые UI-компоненты. Логику управления квартирами предстоит разработать на уроках 41–45.

## Запуск

Понадобятся Node.js 20.19+ или 22+, npm и отдельно запущенный локальный backend Apartment Management.

1. Запустите backend по инструкции из его архива. По умолчанию фронтенд ожидает сервер по адресу `http://127.0.0.1:3000`. Если используется другой адрес или порт, измените настройки `proxy` в `vite.config.ts`.
2. Откройте папку шаблона в VS Code и выполните в терминале:

   ```bash
   npm install
   npm run dev
   ```

3. Откройте адрес, который покажет Vite (обычно `http://localhost:5173`). При первом запуске выберите «Зарегистрироваться», введите имя, email и пароль из не менее чем 8 символов. Тестовый пользователь заранее не создаётся: зарегистрированный аккаунт сохраняется на сервере и подходит для следующих входов.

Для проверки сборки выполните `npm run build`. Прокси `/api` и `/uploads` настроен для локальной разработки через Vite.

## Что готово

- Страницы регистрации и входа, сохранение JWT, восстановление сессии, выход и обработка ответа 401.
- Защищённые маршруты, общий layout, переходы между страницами, страница 404.
- Axios, MobX, типы данных квартиры и базовые UI-компоненты в `src/components/ui`.
- Пустые страницы и разделы формы, пустые хранилища и файл API квартир.

Маршрут редактирования `/my-apartments/:apartmentId/edit` можно открыть вручную для проверки каркаса. Он только выводит идентификатор и не загружает квартиру. Создание черновика, переход к его редактированию после создания, загрузку фотографий и остальные действия предстоит реализовать в ходе практики.

## Работа на уроках

- **41:** запрос и отображение списка квартир, карточки и состояния списка.
- **42:** основные поля, характеристики и состояние формы, получение данных квартиры.
- **43:** выбор, предварительный просмотр и загрузка фотографий, удаление и обложка. Серверу нужен ID существующей квартиры; до реализации создания на уроке 44 для проверки можно создать черновик через API backend.
- **44:** удобства и правила, создание и обновление, проверка и публикация. После создания черновика пользователь переходит на страницу редактирования.
- **45:** управление статусом, удаление, обновление списка и обработка ошибок.

Базовые UI-компоненты экспортируются из `src/components/ui`. Модель `Apartment` и типы вложенных данных находятся в `src/types/apartment.ts`. Список квартир в API может содержать сокращённые данные — для него предусмотрен тип `ApartmentCardData`.
